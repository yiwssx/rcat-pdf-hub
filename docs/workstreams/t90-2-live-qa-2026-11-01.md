## Follow-up: Bubblewrap host /tmp mount-order and minimal runtime exposure

- **Bug found and fixed in the feature branch:** `native_sandbox.isolated_native_command` originally created a private `/tmp` filesystem before binding the source file and native output task directory. T20/T34/T09/T25 decoder output dirs live under the worker's `/tmp`; masking the path first could make the host-side source of a subsequent bind unavailable at Bubblewrap setup. Now it creates the input file RO bind and optional output directory RW bind **before** installing the child-private `/tmp` tmpfs. This is a source-level correctness fix; actual Bubblewrap mount behavior still requires target-host execution.
- **Reduced attack surface:** no longer read-only-mounts the entirety of `/app` and `/opt`. Exposes only `/app/app` (Python application module), `/opt/venv` (pinned Python environment), and optional separately provisioned `/opt/pdfhub/heif` and `/opt/pdfhub/cad` native runtimes read-only. Shared libraries under `/usr` still available; source data and task output only at `/input/source` and `/output`.
- Added `apps/api/tests/test_t90_2_native_sandbox_mounts.py` with command-construction regressions for BOTH source-only and source+output mounts under host temp directories, sandbox network/user namespace flags, no broad application mounts, and input/output overlap rejection. **This new test module has NOT been executed.**
- Added **read-only-in-staging-container** selftest `apps/api/app/services/t90_2_sandbox_selftest.py` which executes the *actual* Bubblewrap argv with a generated source file and verifies the child can read its own source but cannot access `/data`, `/mnt/pdfhub-nas`, root app dotenv, other `/opt` paths, host secrets, or public TCP. **Not executed on RCAT host.** It returns JSON PASS/FAIL/BLOCKED and nonzero exit on denied runtime. Intended command after a QA-stage deployment of the branch:

  ```bash
  docker compose -f docker-compose.yml exec -T worker-heavy \
    python -m app.services.t90_2_sandbox_selftest
  ```

  Do **not** copy the Python file into production and treat the result as an end-to-end format acceptance. Staging must use the actual Python 3.12 pinned image and native flags OFF.
- An independent cross-file source-contract inspection on the connected GitHub branch checked eight key facts (input/output binds before tmpfs, least-privilege runtime mounts, mandatory network/user namespace, selftest invoking the builder, regression cases present): **8/8 matched**. This is static inspection, **not pytest or Bubblewrap runtime evidence**.
